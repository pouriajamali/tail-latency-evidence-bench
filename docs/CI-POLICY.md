# CI resource policy

This workflow policy separates documentation checks from unchanged runtime builds. It does not change application behavior, dependencies, release versions, published assets, account budgets or repository protection.

- Push validation targets the default `main` branch; pull requests retain validation without an extra feature-branch push run. Existing tag patterns are preserved. Ordinary manual dispatch requests full native checks; the separately authorized, single-use M1 route below is the sole exception.
- A narrow documentation allowlist gets real UTF-8/framing, Markdown fence/relative-link and frozen-evidence JSON checks, plus policy contract tests and pinned actionlint. It does not run .NET/C++ builds or upload native artifacts. This is not an exhaustive prose/security audit.
- Runtime/configuration/fixtures/licenses/provenance/pipeline changes and unknown/failed Git comparisons always require the original native checks. Source, Windows/Linux execution, native package inspection and release/provenance commands remain present. Tags and ordinary manual runs cannot take the docs-only route.
- Lightweight checks also statically read the explicit source-package inventories where present, without importing the packager. A new unallowlisted document, symlink mode or computed/unknown inventory cannot hide behind docs-only success.
- Main, tag and manual runs have unique concurrency groups. A docs push cannot replace an earlier pending source run. Only superseded PR runs may be cancelled; classification uses the complete PR delta from its merge base.
- Matrix native jobs use `max-parallel: 1`; Book Replay keeps its two separately defined platform jobs. This is a per-workflow limit, not an account-wide cap. Rollouts are staged rather than starting fourteen heavy runs together.
- Existing native job timeouts remain. Previously unbounded native and comparison/release jobs receive finite timeouts. No source test is replaced by an artificial green check.
- Routine source/PR jobs still build, extract and execute the original native packages, but do not upload the large `bundle-*`, `binary-*` or `tested-*` archives. Finite proof receipts remain. Tag/manual runtime-review runs still upload those required archives; small `checked-source-*` pairs remain on ordinary runs because downstream byte-comparison jobs consume them. No source/native check or release gate is replaced by this upload saving.
- Future Actions uploads retain ordinary source/PR artifacts for **3 days**, and tag/manual review artifacts for **7 days**. These are temporary CI artifacts. Published release archives, checksums, signatures and keys are separate and remain immutable.
- New retention does not delete old artifacts or logs. No artifact/cache deletion, paid capacity, self-hosted runner, account permission or budget change is performed by this policy. Any historical cleanup requires a separately reviewed inventory and explicit authorization.

The lightweight job uses only the standard Ubuntu runner, Python's standard library, and actionlint 1.7.12 downloaded from its official release with an exact archive SHA256. It does not claim optional external ShellCheck/Pyflakes results. Current account storage usage is not inferred from one repository's artifact byte count.

## Single-use M1 consumer profile

The task branch codex/wave4-m1-record-cap-20261117 adds an explicit m1_once manual input with verify_release=false. It runs one fixed Windows qualification and, only after admission, the original three Windows raw-capacity cases. The local canonical controller then runs the original three Linux cases in the existing Ubuntu-24.04 WSL distro. This route does not run the ordinary build/demo/test jobs, install an SDK, rebuild or publish the frozen runtime. All ordinary events retain their existing gates.

The local controller owns the real canonical CreateNew lease throughout the single 300-second window (270 work / 30 terminal). A signed, expiring source-commit ticket binds project, owner process, nonce, exact source manifest, canonical protocol/path hashes, run and six-case order. The runner never claims a copied lease. Only run_attempt=1 and the first dispatch for that source commit can consume the ticket; retries, reruns and expiry fail closed. Unknown terminal evidence retains the real lease for explicit recovery.

Windows admission keeps the original exact Python 3.12.10, PowerShell 7.6.9 and SSH hashes and original OS_BASE/provider predicates. A documented version match alone is insufficient. Children start suspended, join their own kill-on-close Job, and verify actual membership, birth and readback: 512 MiB, 16 active processes, CPU rate 1000 and at most two affinity processors. Each import-only role has 20 seconds; both share 60 seconds. No provider allowlist, antivirus, system policy, ACL or repository protection is changed.

The existing qualifier, fixed acquisition/extraction guards, independent witness and frozen oracle are reused. Qualification is limited to 64 MiB new reads, 256 consuming files and 1 MiB combined role proof. Scratch is 1 GiB and proof 8 MiB. Each physical host fetches only its fixed RID archive once; combined transport stays below 75 MiB. The three retained public signature/key/checksum assets are reused. Every native child remains bounded by 45 seconds, its controller phase by 60 seconds, and the same outer deadline. Linux inherits the existing 200% CPU / 512 MiB / swap 0 / 64-task cgroup. Its metadata-derived vendor scope is explicitly partial; it never claims global closure or advisory qualification.

A successful admission permits only raw capacities 99, 100 and 101 once per RID, with the original fixed configuration. Both validator modes consume those same immutable datasets and 12 negative controls per RID. Frozen oracle false positives remain reported. No old healthy regression, demo, SDK build, performance retuning or broad snapshot is repeated. A failed gate is M1 HOLD, not completion. Public CI artifacts retain only safe proof for seven days; private canonical ownership and recovery receipts stay local. Existing preview assets remain unchanged.
