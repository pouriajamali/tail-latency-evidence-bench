# Contributing

Use synthetic counterexamples with explicit expected counts and chronology. Start with hand-worked accounting/rank tests, the native demo and independent raw oracle. Keep a slower or failed run visible instead of tuning until a desired number appears.

A reviewable change states what input is rejected, what is missing at cutoff and which executable evidence proves it. Preserve raw data, bounded limits and clock domain; do not add live feeds, accounts, orders, production deployments, unsafe structures or invented team/management claims.

Do not change unrelated portfolio/CV/private/shared assets. Tool/source changes require pinned supported versions, true shipped-graph notices and honest native package/CI/public-download boundaries.
